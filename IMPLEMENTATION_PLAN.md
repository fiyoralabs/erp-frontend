- [x] Backend issues found, fixed 2026-08-03 (all confirmed live against real Postgres before and after):
  1. **Critical, blocked the whole module**: `GET /products/{id}` (and update/activate/deactivate, which return the same shape) 500'd for *every* product, always. Root cause: `Product.java`'s `unit` field, and the shared `EntityReferenceFactory.unit()` helper, both referenced the wrong JPA entity (`com.fiyora.erp.common.domain.entity.Unit` → legacy `common.unit` table) instead of `com.fiyora.erp.master.domain.entity.Unit` (real `master.unit` table, same one the Master Data Units screen manages). Every real unit id lives in `master.unit`, so the lazy-load always threw `EntityNotFoundException`. Fixed both files.
  2. **Systemic, 5 endpoints**: every *update* endpoint in this module (Product/Variant/Barcode/Image/Price) 500'd if the caller omitted an optional field, because MapStruct's default partial-update mapping overwrites the target with `null` when the source field is absent, and several of those fields are `@NotNull` at the entity level (e.g. `ProductPrice.effectiveFrom`). Fixed all 5 mappers with `@BeanMapping(nullValuePropertyMappingStrategy = NullValuePropertyMappingStrategy.IGNORE)`, the standard MapStruct pattern for partial updates -- not just the one (`PriceMapper`) that surfaced it first.
  - Minor, not fixed: `createdAt` returns `null` on create responses for Variant/Barcode/Image/Price (cosmetic, entity isn't refreshed after insert to pick up the DB-default timestamp).
